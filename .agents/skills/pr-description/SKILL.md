# PR 디스크립션 작성

TRIGGER — PR 디스크립션 작성, PR 본문 작성 요청 시 이 스킬을 먼저 로드.

## 템플릿

`.github/pull_request_template.md`를 반드시 따른다.

## 자동 수집 (사용자 입력 불필요)

아래 항목은 git 정보에서 자동으로 추출한다:

- **주차**: 브랜치명에서 추출 (예: `feat/week-01-...` → `Week 01`)
- **무엇을 / 왜**: `git log main..HEAD`와 `git diff main...HEAD --stat` 기반으로 초안 작성, 사용자 확인 후 확정
- **AI 활용 범위**: 사용한 도구와 작업 범위, 사용자의 검토·수정 여부를 본문 끝에 2–3줄로 자동 추가

## ✅ 선행 검증

PR 디스크립션 요청을 받으면 사용자에게 완료 여부를 묻지 않고, 현재 변경을 기준으로 아래 2가지를 **직접 실행**한다:

1. **`self-review` 스킬** — 전체 diff를 6단계 + 문서-코드 동기화 점검
2. **[FSD 검증 규칙](../../../.claude/rules/fsd-verification.md) 검증** — 파일 배치·Public API·슬라이스 경계 확인

### 검증 기준 기록

검증을 시작할 때 다음 값을 수집한다:

- base 브랜치와 base commit SHA
- 현재 HEAD commit SHA
- `git status --short`
- 검토 범위: `base...HEAD`의 커밋 diff + staged·unstaged·untracked 작업 트리 변경

### 과거 결과 재사용

과거 self-review/FSD 결과는 아래 조건을 **모두** 만족할 때만 재사용한다:

- 결과에 base 브랜치·base SHA·HEAD SHA·검증 시각이 기록되어 있다.
- 기록된 base SHA와 HEAD SHA가 현재 값과 일치한다.
- 기록 당시와 현재 작업 트리가 모두 clean이다.
- self-review 6단계 결과표와 FSD 체크리스트 결과가 모두 있다.

하나라도 확인할 수 없거나 값이 달라졌다면 과거 결과를 완료 증거로 보지 않고 두 검증을 다시 실행한다.

### 중단 기준

self-review에서 해결되지 않은 Critical·Major가 있거나 FSD 체크리스트에 실패 항목이 있으면 PR 본문 작성을 중단하고 다음 형식으로 먼저 보고한다:

```
선행 검증에서 먼저 해결해야 할 항목이 발견되었습니다.

- Self-review: Critical N건, Major N건
- FSD 검증: 실패 N건
- 검토 기준: <base SHA>...<HEAD SHA> + 작업 트리 변경
```

Minor·Suggestions만 있으면 해당 내용을 사용자에게 알리고 PR 디스크립션 작성을 계속할 수 있다.

## 사용자 입력 필수

아래 항목은 사용자에게 반드시 질문하여 받는다:

1. **학습 주제**: 이번 과제를 통해 학습한 주제
2. **배운 것 / 새로 적용한 것**: 새로 배우거나 적용해 본 내용
3. **고민한 점 / 막혔던 부분**: 선택을 두고 고민한 것, 어려웠던 것, 미해결 사항
4. **피드백 받고 싶은 부분**: 리뷰어가 집중해서 봐줬으면 하는 부분

## 작성 절차

1. base·HEAD SHA와 작업 트리 상태를 기록하고 검토 범위를 확정
2. 현재 검토 범위로 `self-review`와 FSD 검증을 직접 실행
3. Critical·Major 또는 FSD 실패가 있으면 발견 사항을 보고하고 중단
4. `git log`, `git diff --stat`으로 변경 사항 파악
5. 사용자에게 필수 입력 4가지 질문
6. 템플릿에 맞춰 디스크립션 조합
7. 본문 끝에 **AI 활용 범위**를 2–3줄로 구체적으로 추가
   - 사용한 AI 도구와 AI가 수행한 작업(예: 구조 대안 제안, 코드 초안, 문서 정합성 검토)을 명시한다.
   - 사용자가 직접 판단·검토·수정한 범위를 함께 적는다.
   - 단순히 “AI로 초안 작성”처럼 포괄적인 한 줄로 끝내지 않는다.
